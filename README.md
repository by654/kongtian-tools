# 空天工具合集 · Kongtian Toolbox

浏览器里的万能工具箱。**纯前端、本地处理、文件不上传**，整合 36 个分类、252 个工具，覆盖文本、编码、开发、数据、图片、PDF、音视频与文件格式转换，手机与电脑使用同一套响应式界面。

- 在线访问：<https://by654.github.io/kongtian-tools/>
- 本地访问：`http://localhost:8787/`（见下方「本地运行」）

## 特点

- **纯前端**：没有后端、没有数据库、没有账号；所有计算、转换、编解码都在浏览器内完成。
- **文件不上传**：图片、PDF、音视频只读取到内存或本地存储，不会离开设备。
- **依赖按需加载**：工具代码按分类懒加载；第三方库只在打开对应工具时下载，并在页面顶部实时显示依赖名称、体积与下载进度。
- **一处代码，两端一致**：同一套响应式布局服务手机与电脑，触屏操作与键盘操作都可用。
- **好找、好开**：分类浏览、全局搜索、`Ctrl/⌘ + K` 命令面板、收藏、最近使用、独立深链接。
- **可安装 PWA**：支持添加到主屏幕与离线缓存应用外壳。

## 功能合并与去重

站内同类工具不再并列堆叠：功能重复的工具合并为同一工具下的并列标签，A 功能包含 B 功能的以 A 为主工具、B 收为子标签。被合并的实现原样保留、按需加载，能力没有删减。

- 合并后工具 252 个，比整合前的 275 个减少 23 个重复入口，分类由 37 个收敛为 36 个（PDF 文档并入文件转换）。
- 14 个主工具采用多标签结构，例如「PDF 工具箱」内含转换引擎、合并拆分、页面信息、文本提取、PDF 转图片、水印页码、手写签名。
- 旧链接仍然可用：访问 `#/t/pdf-merge`、`#/t/image-resize` 等被合并工具地址会自动跳转到主工具并定位到对应标签。
- 合并关系集中在 `assets/js/core/merge-map.js`，由 `assets/js/core/merge.js` 渲染标签页；本地 `node check.mjs` 会校验每个标签的实现是否存在。

## 依赖按需加载

打开需要第三方库的工具时，页面会显示「正在下载运行依赖」面板，逐个展示：

- 依赖名称与用途（例如 `pdf-lib · PDF 创建与编辑`）
- 实时下载进度百分比与进度条
- 完成后的总大小与「已缓存」状态

轻量依赖清单：marked、DOMPurify、JSZip、pdf-lib、PDF.js、Chart.js、PapaParse、js-yaml、math.js、SheetJS、Tesseract.js、jsQR、qrcode-generator、JsBarcode、KaTeX、sql.js，通过 jsDelivr 加载。

文件转换引擎涉及的第三方库（ffmpeg.wasm 及核心 wasm、pdf-lib、PDF.js 与 worker、mammoth、SheetJS、JSZip、marked）随仓库放在 `vendor/` 目录，第一次使用某个格式时从本站加载并缓存，不依赖外部 CDN，音视频转码同样在本地完成。

## 本地运行

需要 Node.js 18+：

```bash
node server.mjs . 8787
```

终端会输出：

```text
本机访问: http://localhost:8787/
局域网访问: http://192.168.x.x:8787/
```

手机与电脑连接同一局域网后，打开局域网地址即可访问。也可以使用任意静态服务器：

```bash
python -m http.server 8787
# 或
npx serve .
```

## 部署到 GitHub Pages

1. 将仓库推送到 GitHub。
2. 打开仓库 **Settings → Pages**。
3. Source 选择 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`。
4. 保存后等待 1–2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`。

也可以使用 GitHub CLI：

```bash
gh api -X POST repos/<owner>/<repo>/pages -f 'source[branch]=main' -f 'source[path]=/'
```

## 隐私与边界

- 摄像头、麦克风、剪贴板、定位等权限只在你主动使用对应工具时请求。
- 加密、医疗、法律、金融相关工具只做本地计算或模板，不构成专业建议。
- 需要服务器或第三方 API 的能力（实时汇率、短链、IP 查询、邮件发送等）不做伪装实现。
- 部分重型能力（OCR、本地大模型）受浏览器性能与网络限制。

## 技术栈

原生 ES Modules + 原生 CSS，无构建步骤。文件处理使用 File API / Canvas / Web Audio / MediaRecorder / WebCrypto / IndexedDB，PDF 使用 pdf-lib 与 PDF.js，音视频转码使用 ffmpeg.wasm，文档互转使用 mammoth 与 SheetJS，图片 OCR 使用 Tesseract.js，二维码使用 qrcode-generator 与 jsQR。
